# Movement and network parity notes

Source authority: the pinned `reference-upstream/src/main/java/me/ionar/salhack/module/movement` and `module/exploit` sources. This group adds 21 real modules through `ExpansionMovementModules.register(ModuleManager)` and `salhack-movement.mixins.json`. Existing AutoWalk/ElytraFly/NoSlow/SafeWalk/Speed/Sprint/Step/Yaw registrations are untouched.

## Lifecycle and interaction boundaries

- All effects are dormant when modules are disabled; packet hooks additionally verify the active play connection and client thread. Background/non-play traffic is not intercepted.
- Blink's queue and fake entities belong to one world and connection. Fake entities use unused negative IDs. Releasing after death/disconnect/world change cannot replay packets to a new world.
- EntityDesync only reinstates a removed vehicle into its original world when its ID is still unused; explicit server destruction clears ownership first. Restoration uses an invoker for the protected removal reset, not NBT reconstruction.
- Ghost and NoFall bucket/equipment state track the specific player object. Elytra restoration can remain pending while a container is open, then completes when safe; after disconnect a server inventory may remain with elytra equipped because no speculative writes are sent into another session.
- Sneak releases only the key it owned. Mouse-bound sneak restoration is conservative (false); ordinary default keyboard bindings are restored from physical state.
- Competing Flight/PacketFly/ElytraFly or movement modules may request different velocity each tick. No automatic mode arbitration is added. PacketFly's generated pair and Blink replay bypass this group's outgoing hooks to prevent self-cancellation/retransformation; PacketCanceller still applies to ordinary packets.
- CrashExploit and obsolete duplication coordination are deliberately excluded, per the approved scope. NewChunks is owned by the rendering group.

## Validation

`gradle compileJava test --tests '*MovementMathTest' --offline` passed with bundled Java17/Gradle8.6 after the other groups' compile errors were resolved. Three tests cover normalized diagonal movement/rotated axes, relative negative-coordinate teleport calculation, and bounded FIFO buffering with cross-session discard. Mixin annotation processing accepted the hooks at compile time. Actual game startup/application of every mixin and multiplayer server acceptance require coordinator runtime verification; compilation is not a claim that flight, nofall or historical protocol bypasses succeed on a current server.
