# Render expansion: original behavior, implementation, and verification

Authority: pinned `reference-upstream/src/main/java/me/ionar/salhack/module/render`, `module/exploit/NewChunksModule.java`, and `util/render/ESPUtil.java`. This is a behavior inventory, not a claim that a count of registered modules establishes parity. Existing Brightness, EntityESP, StorageESP, Tracers, Nametags, Waypoints and HUD remain coordinator-owned and are not reimplemented here.

## Integration

Call `ExpansionRenderModules.register(ModuleManager)` once before applying profiles. Include `salhack-render.mixins.json` in Fabric metadata. The registration owns one world render event, one overlay tick, Freecam validation at START_CLIENT_TICK, and shulker tooltip/cache callbacks. Hook files use Inject callbacks only: no exclusive Redirect or ModifyConstant hooks. Dormant checks precede feature behavior. Scans never request unloaded chunks.

## Bounds and cleanup

Hole scans are incremental. Void scans at most 4225 columns of five positions every ten ticks. Chunk observations scan at most 33x33 loaded chunk coordinates every ten ticks with at most 8192 history entries. City scan is four positions per nearby loaded player. Projectile stepping stops after 240 segments. Render positions are translated relative to the active camera with push/pop around all owned matrices. Own render layers configure and restore depth/blend/culling around their flush; Fabulous-specific framebuffer appearance and alternate shader packs still need visual checking. Entity iteration uses the current loaded client entity collection. There are no network requests or block/chunk loading requests.

Freecam never claims ownership of player flight/noclip flags. It owns only its temporary camera and keyboard routing, and reverts those on disable. Camera is never inserted into the world's entity list, so it cannot create a fake attack target or duplicate server entity ID. Shulker cache/poses/diagnostic collections reset on world identity change. Profile settings alone do not establish that effects work.

## Evidence and remaining runtime work

`compileJava compileQaJava --offline --console=plain --no-daemon` succeeded on Java 17 / Yarn 1.20.4 build 3 / Fabric API 0.97.2. The only render compiler note is existing modern deprecated rendering API use. This proves source/type/mapping compilation, not mixin application or pixels.

`src/qa/java/me/ionar/salhack/qa/RenderParityChecks.java` provides `run(MinecraftClient)` for the temporary QA world. It tests actual look routing and input/movement mixin application; detached camera movement; packet selection; disable restoration; actual NBT-driven shulker getTooltipData injection and dormant disabled behavior. It restores toggles/settings/keys in finally. Coordinator must execute it in the integration client and record its output. Before release, verify all render modules together, multiple mode/color choices, block break events from another player, middleclick viewer/EnderChest cache, Freecam during correction/death/dimension/disconnect, and KTHREADD coexistence. None of these visual/network scenarios is asserted proven by compile alone.
