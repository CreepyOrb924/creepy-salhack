# Automation implementation and remaining parity work

This group adds 37 functioning registrations through `ExpansionAutomationModules.register(ModuleManager)`. This is **not complete original parity**. In particular, the builders, mining modes, schematic workflow and notifications remain reduced. Compilation and seven pure tests pass; actual in-game behavior has not yet been exercised by this group. Coordinator integration/runtime QA is required before distribution.

## Integration

- Add `ExpansionAutomationModules.register(this)` once in ModuleManager; the registrar installs Fabric callbacks once.
- Include `salhack-automation.mixins.json` in Fabric metadata. It has eight client mixins: AutomationClientMixin, AutomationNetworkMixin, AutomationPlayMixin, AutomationInteractionMixin, AutomationSignMixin, AutomationChatMixin, AutomationTimerMixin, AutomationBlockItemMixin.
- Friends use shared `profile.friends`. `ExpansionAutomationModules.isFriend(name)` additionally honors the original Friends enable/disable switch. Core combat predicates must honor that switch too. MiddleClick modifies the shared profile and marks it dirty.
- CoordSpoofer belongs in coordinator HUD integration: its original module is empty and its only behavior is performed by the original coordinate HUD. It is not registered by this group.

## Missing or outside this group

- CoordSpoofer: coordinator HUD task, not silently counted here.
- Stopwatch live HUD and full original notification visuals: coordinator/render follow-up.
- Existing AutoRespawn, AutoTool, ChestStealer, NoWeather, StashFinder, Waypoints, Colors, HUD and ClickGUI were intentionally not duplicated or upgraded by this group. Their earlier reduced settings/behavior remain separate parity work. In particular existing StashFinder is **not** the original Hilbert flight path.
- DiscordRPC is deliberately not implemented: native RPC remains an optional dependency decision. No Discord telemetry or server/account disclosure was added. All original RPC settings (Username, ServerIP, DetailsAddon, Ionar, Speed, Movement, Crystalling, Health, GitHub) are absent.
- AutoDuper/ManualDupe, account manipulation and obsolete duplication exploits remain excluded per project scope.

## Verification and runtime risks to resolve

- `compileJava test --offline` using workspace JDK17/Gradle8.6: successful after final compilation at this stage.
- `ChatTransformsTest`: command-prefix preservation, all-decoration composition, independent FancyChat behavior, surrogate-safe 256-character bound.
- `BuildPlansTest`: portal boundary/interior, highway width/uniqueness and wither soul-sand-before-skull ordering.
- Seven pure tests do not verify inventories, network acknowledgements, mixin runtime application, server block placement, GUI behavior, disconnect retry flow, or dual-client coexistence. Do not install or call full parity based on compilation alone.
- XCarry and forced early mining are server-dependent original behaviors; retained toggles request client behavior but do not claim server acceptance. ForceCancel can intentionally retain other container state until another close; server constraints remain.
- Inventory modules avoid containers/cursor contention, never throw/drop items, and use bounded normal slot actions. Actual server rejection paths and disabling during GUI changes still need game QA.
- Builder modules can interact with an adjacent usable support (for example a chest) instead of placing unless vanilla sneaking is held; automatic sneak ownership is not implemented. This is a documented limitation, not a claimed completed placement.
